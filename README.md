# מנוע חילוץ טפסי התחייבות

קורא טפסי התחייבות (PDF / תמונה), מחלץ שדות עם רמת ביטחון, שומר רשומות במסד נתונים מקומי, ומאפשר תיקון, אישור וייצוא.
הארכיטקטורה והכללים המלאים: `CLAUDE.md`. הפעלה: `streamlit run app.py` (מפתח Gemini ב-`.env`, ראו `.env.example`).

## נתונים שנשמרים מקומית (פרטיות)

| מה | איפה | מתי נמחק |
|---|---|---|
| רשומות, מצבי שדות, יומן שינויים, העלאות | `data/app.db` (SQLite) | "מחק את כל הנתונים" (מסך הרשומות, "ניהול נתונים", בתחתית), או מחיקה ידנית של הקובץ |
| תמונת כל עמוד שיש לו רשומות | `data/pages/<מזהה העלאה>/p<עמוד>.jpg` (מספרים בלבד בשמות; שם הקובץ המקורי לא נשמר) | אוטומטית כשכל הרשומות של העמוד אושרו; ב"מחק את כל הנתונים"; או מחיקה ידנית של התיקייה |
| מוני מכסה (בלי נתוני מטופל) | `data/quota_state*.json` | ידנית |
| מטמון תשובות המודל (רק ב-`PRIVACY_MODE=dev`) | `data/cache/` | ידנית |

- `data/` כולל נתוני מטופלים ונמצא ב-`.gitignore`. אין להעלות אותו ל-git.
- **איפוס המערכת למצב ריק:** מחיקה ידנית של `data/app.db` ושל התיקייה `data/pages` (כשהאפליקציה סגורה). הם ייווצרו מחדש בהעלאה הבאה.
- "מחק את כל הנתונים" סופי ואינו משפיע על קבצים שכבר הורדו (Excel / CSV / JSON).
- המסד והתמונות נכתבים בשני מצבי הפרטיות (`PRIVACY_MODE`); המצב שולט רק במטמון ובקובצי הדיבוג.

### הגדרות אחסון תמונות (`config/storage.json`)

| מפתח | ברירת מחדל | משמעות |
|---|---|---|
| `store_page_images` | `true` | `false` = לא נכתבת אף תמונת עמוד (כרטיס הרשומה יציג "אין תמונה שמורה לעמוד הזה", והעריכה ממשיכה לעבוד) |
| `keep_images_after_approval` | `false` | `false` = התמונה נמחקת כשכל הרשומות של העמוד אושרו; `true` = היא נשארת |

אפשר לדרוס בסביבה: `STORE_PAGE_IMAGES=0`, `KEEP_IMAGES_AFTER_APPROVAL=1`. בשימוש במעבדה, עם מטופלים אמיתיים, יש להחליט במפורש אם לשמור תמונות.

## בדיקות

`python -m pytest -q` (בלי קריאות API: הבדיקות משתמשות בלקוחות מדומים ובריצות שמורות).

## רשימת הגורמים השולחים

הרשימה הסגורה יושבת ב-`config/senders.json` (ללא קוד): `canonical` = שם קנוני -> כינויים, `hmos` = קופות החולים, `branches` = סניף / מוסד -> קופת אם,
`lab_names` = שמות המעבדה המקבלת (מוחרגים תמיד), `ambiguous` ו-`keyword_required` = כינויים דו-משמעיים (ראו למטה). כינויים שנלמדו מתיקונים
ידניים נשמרים ב-`config/aliases.json`. המקורות: ארבע קופות החולים (כללית, מכבי, מאוחדת, לאומית) ובתי החולים מרשימת בתי החולים בוויקיפדיה ומרשימת
המוסדות של משרד הבריאות, כולל רשימה שנאספה ידנית (`data/institutions_friend.txt`, 49 שמות). ההנחות כאן הן הנחות שלנו ולא כלל רשמי של המעבדה.

**להוסיף מוסד בלי לשנות קוד:** מוסיפים ל-`canonical` שורה חדשה `"שם המוסד": ["שם רשמי מלא", "קיצור", ...]`. לא משנים שם קנוני קיים (הבדיקות,
טבלת האמת והדוחות השמורים משתמשים בו; אפשר רק להוסיף לו כינויים). כינוי הוא תת-מחרוזת בטקסט (אחרי נרמול: גרשיים וסימני פיסוק מוסרים, "המרכז הרפואי"
= "מרכז רפואי", "בית החולים" / ביה"ח = "בית חולים"). כל אתרי אותו מוסד (למשל אסותא) הם ישות אחת. שני מוסדות שונים עם שם דומה
(האיטלקי בחיפה והמשפחה הקדושה בנצרת) הם שתי ישויות, וכינוי בלי עיר ("האיטלקי") לא מתאים לאף אחת: גורם לא מוכר = "אחר", כתום.

**כינוי שהוא גם שם פרטי / משפחה / רחוב / מילה רגילה** (כרמל, רבין, כללית, לאומית...) נכנס ל-`ambiguous`: הוא מותר רק כמילה שלמה, ורק אם האזכור הוא
לוגו / כותרת / חותמת / שדה הקופה בתיבת המטופל, או שבאותו טקסט יש מילת מפתח של מוסד (קופת חולים, מרכז רפואי, בית חולים, ביה"ח, ה.מ.).
שם בודד שהוא שם פרטי או משפחה (אלישע, רפאל, קפלן, זיו, הלל, מאיר) נכנס גם ל-`keyword_required`: דרושה מילת מפתח תמיד, גם בלוגו. אל תוסיפי לו כינוי בודד.
ההתאמה המקורבת (fuzzy) ובדיקת שם המעבדה משווות מילים מבדילות בלבד (בלי "מרכז רפואי", "בית חולים"...), כך ששני מוסדות עם אותן מילים גנריות לא נראים דומים.

**הערת שקיפות:** עמודת הגורם השולח של חלק 2 (`truth_part2.xlsx`) נצפתה פעם אחת בזמן ביקורת על הרשימה, ולא שימשה לשום שינוי בכינויים, בכללים או בציפיות.
